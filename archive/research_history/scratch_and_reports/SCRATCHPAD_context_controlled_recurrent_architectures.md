# Scratchpad: context-controlled recurrent architectures

Working decisions and verification notes; not a scientific report.

- Model A is a single-layer GRU-150 over token plus 42D observable evidence.
- Models B/C use an 8D GRU controller over token plus observable evidence. The Elman-128 task core sees token plus ordinal position; context enters through the controller projection. C gates the previous core state before the shared recurrent transform.
- No model `forward` signature accepts a latent label. Latent A/B is generator metadata used only to realize the target sequence and compute frozen oracle diagnostics.
- A world is one continuous 36-sequence recurrent stream, allowing task history to inform context. The prescribed 10 clear-A, 10 clear-B, 10 alternating, and six ambiguous schedule contains 18 examples of each cause.
- Shared task structure dominates: A modifies P2/P3 and B modifies P5/P6 relative to a world-specific shared sequence; P1/P4/P7 remain shared-heavy.
- The shuffled cell is created from the fully realized structured world and permutes task-regime assignments across the same 36 evidence observations. Evidence, tasks, cause counts, ambiguity, and updates are identical as multisets.
- Synthetic loss is only next-token cross-entropy. RT, context labels, gates, hidden distance, corridors, and oracle posterior never contribute gradients.
- Oracle context decoding is post hoc, within-world ridge decoding: clear observations fit the decoder and ambiguous observations are held out. This respects each world's anonymous, independently sampled cause surface and never changes recurrent parameters.
- Human transfer is unreachable in smoke/pilot modes. Confirmatory mode requires the saved pilot gate, trains only pilot-passing architectures, selects at most two without human probe access, then uses the locked G2/A10-B10/170-sequence target contract.
- The H8 comparator calls the original `SRNEngine` directly. Restricted plasticity freezes only the shared Elman core and leaves the controller, context projection, and prediction head trainable.
- Interventions are executed under `torch.no_grad()` and guarded by pre/post model hashes.
- Long synthetic cells checkpoint model, optimizer, completed-world index, training rows, and manifest under `outputs/.../checkpoints`. Rerunning the identical config/profile resumes at the next world; any architecture/condition/seed/scale/config mismatch is rejected.
